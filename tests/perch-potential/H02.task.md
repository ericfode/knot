# Maintain multiset query results under changes

Input tables are finite multisets of typed tuples. Queries use selection by a
supplied total predicate, projection, multiset union and equality join. The
snapshot result includes each output tuple and its multiplicity. Projection
adds multiplicities for equal projected tuples; union adds multiplicities;
join multiplies multiplicities for each matching pair before collecting equal
outputs. Query structure is supplied at runtime, not fixed per table.

Tables also receive batches of signed multiplicity changes. Applying a batch
must leave every table multiplicity nonnegative. Return the exact signed change
to the query result without reevaluating portions of the query unaffected by the
changed input relations. Simultaneous changes on both sides of a join must
include their interaction. Applying two valid batches separately must agree,
including the net output change, with applying their combined change at once.

Each input occurrence has a stable token. Every output must retain an explanation
of which combinations of input occurrences contribute to it, including duplicate
derivations. Counting those contributions must recover its multiplicity.
Removing occurrences must remove precisely their contributions. Explanations and
changes must agree under equivalent query reassociation and distribution, not
just produce the same final tuple set. State the conditions under which partial
results can be cached or replaced while preserving all these observables.
