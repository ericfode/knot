# Base slice fixture suite (campaign increment 8)

This suite freezes the expectations for increment 8 of the
[compiler campaign](../../docs/COMPILER-CAMPAIGN.md): lowering the Base slice
that Knot's own frontend and compiler reach. Under D2, Knot loads the
hash-pinned, unmodified `base.bend` and lowers only that reachable slice. Under
D7, these expectations were fixed before implementation and independently of
the implementer. Seed-valid programs take their results from the pinned
reference interpreter, Bend 2.0.29 at `574b6d3`. Knot-specific outcomes are
reviewed literals. Nothing here comes from Knot's output. Under D4, Knot reports
a form it cannot yet check as `Unsupported`, never as `Invalid`, and never
passes it through unchecked.

The implementer wires the gate runner and does not edit these expectations.
Changing a fixture, a case or a pinned outcome is a separately reviewed amendment.

```sh
python3 tests/compiler-baseslice/regen.py            # verify; exit 1 on any difference
python3 tests/compiler-baseslice/regen.py --write    # rewrite observations only; review the diff
python3 tests/compiler-baseslice/regen.py --census   # compare base_slice with the live census
```

## Contents

- `fixtures/*.bend` holds 40 programs, one Base family or edge each.
  - Every fixture starts with `import Base` and is ASCII with LF line endings
    and no tabs.
  - Each declares its own nullary enums. No local type, constructor or
    definition reuses a Base name.
  - Seed-valid fixtures have a `main` plus a few entries. Every entry takes and
    returns only enums declared in the fixture, because the host boundary is
    enum-only. Base values (`String`, `List`, `U32`, `Nat`, `Maybe`, `Result`,
    pairs, `IO`) are built and consumed inside the program.
  - Where a fixture mirrors a Knot source function, a comment names it, for
    example `catalog.field_kind` or `driver.natural`. "Verbatim" means that the
    body matches Knot's, apart from spacing and `S.` qualification.
- `expectations.json` has these sections:
  - `seed`: must equal `src/CONTRACT.json`.
  - `commands`: how every observation was produced.
  - `requirements`: the four Knot requirement kinds, defined below.
  - `capabilities`: the ladder vocabulary used by `requires`.
  - `forms`: the lowering demands found in Base bodies, each mapped to the
    capabilities it needs.
  - `base_slice`: the frozen projection of the census. It lists the 72 reached
    Base entries with roots, per-lane boundary, reviewed forms and
    slice-internal dependencies.
  - `cases`: hand-reviewed metadata for each fixture: class, family, intent,
    twin, needed capabilities, entry signatures, the seed's rejection reason
    and the Knot requirement.
  - `observations`: generated by `regen.py`, as described in the next section.
- `regen.py`: re-runs the seed and diffs the output against `observations`.

## What `regen.py` records and checks

`observations` holds the seed file hashes and, for each fixture:

- its source hash and enum constructor orders;
- the Base names it spells, the part of the slice those names reach through the
  frozen dependency edges, and the union of the reached entries' forms;
- its `--check-only` and direct-run results;
- every entry call: the wrapper source, argv, exit, exact stdout and stderr,
  and `{type, constructor, tag}`;
- for a negative, the single line that differs from its twin.

It also holds a `coverage` table that maps each slice entry to the fixtures
that spell or reach it.

Verification fails in any of these cases:

- the seed identity, the seed file hashes or `bend version` change;
- a fixture is edited, added or removed, or its entry signatures drift from the case;
- a requirement is malformed;
- a fixture uses a local name that Base also uses;
- a fixture spells a Base name outside the frozen slice;
- a case's `requires` omits a capability that its reached Base forms need;
- the seed accepts a negative, or rejects a fixture that is not a negative;
- a negative's `seed_reason` substrings are missing;
- a negative differs from its `agree` twin in more than one line;
- a seed-valid entry takes or returns anything other than a local nullary enum;
- every call of an `agree` or `agree-or-unsupported` fixture returns the same
  constructor, since a constant answer would then pass;
- a slice entry that is not a host effect lacks an `agree` fixture that reaches it;
- a host entry lacks a pinned `unsupported` fixture that reaches it, or an
  `agree` fixture reaches one;
- the seed times out (after 120 s), which is never recorded as a result;
- an output contains a checkout-specific path.

`--write` builds the observations twice and writes only if both passes agree.
One verification pass takes about 40 seconds. Wrappers are written to the
ignored `.local/compiler-baseslice/wrappers/`. A direct `main` run prints an
unqualified constructor such as `Lit{}`. A wrapper call prints
`../../../tests/compiler-baseslice/fixtures/<case>.Lit{}`, and `result` strips
that prefix.

Reach is a static upper bound, not an execution trace. A fixture spells a name
directly, or through a constructor such as `SCon` (which gives `String`) or
literal sugar (`"..."`, `'c'`, numerals, `[..]`, `<>`, `&` and tuples, and
`do IO<..>`). The frozen census edges then close that set. A reached helper is
statically reachable. That does not mean every one of its branches runs.

## The reached Base slice

`base_slice` projects `docs/compiler-campaign/inventory/base-closure.json`
(census commit `ff83775`). It takes the runtime JS closures of the `frontend`
roots (`src/lex.tokenize`, `src/parse.parse`) and the `compiler` root
(`src/compile-cli.main`), keeps the entries whose file is Base, adds the native
boundaries, and restricts the dependencies to the slice. The frontend reaches 39
entries and the whole compiler 72. Without the two word representations, `Nat`
and `U32`, those counts are 37 and 70: the "about 37" and "about 70" of the
increment brief. `--census` confirmed at freeze time that the projection
matches the live census. The census file itself is not hashed into
verification: it also lists every non-Base closure entry, so any `src/` change
would otherwise break this suite.

The brief also named `String.length`, String chars, `List.map`, `List.fold` and
Char classification. None of them is in the census closure. Knot uses
`Char.to_u32` with `U32` comparisons, as `syntax.alpha` does, instead of
`Char.is_alpha` and its siblings. It also never calls `List.map`, the folds,
`String.length`, `String.to_list`, `Maybe.*` or `Result.*` functions. Their
absence is not a coverage gap. Because regen rejects spellings outside the
slice, these fixtures cannot drift into them.

### What lowering these bodies demands

These demands come from reading each reached body in `base.bend`. The per-entry
`forms` are in `base_slice`. Most map to earlier rungs: fields (2), patterns
(3), literals and intrinsics (5), generics (6) and closures (7). A fixture
whose rungs are not yet available is blocked. The runner reports it as blocked,
never as passing, and never re-expects it.

Six demands have no earlier owner, so they are this increment's own work:

- **Law-declared signatures.** `String.cmp`, `String.starts_with`,
  `U32.read.go` and `U32.show.go` are untyped `def`s typed by a preceding
  `law`.
- **Mutual recursion through helpers.** Four cycles:
  - `String.cmp` and `.fin`;
  - `String.starts_with` and `.if`;
  - `U32.read.go` and `.if`;
  - `U32.show.go` and `.fin`.

  The milestone 1 contract covers only direct self-calls. In these cycles the
  descent happens across the cycle: `String.cmp.fin` calls `String.cmp` on its
  own parameter 0, which is a field of `String.cmp`'s argument.
- **Tuple destructuring.** `((a2, b2), c) = r` appears in `String.eq.fin`,
  `String.cmp.fin` and `String.cmp.rec`, and `Char.cmp` builds tuples. Knot
  now reports a destructuring binding as `Unsupported parse
  destructuring-binding`, and Base needs it for `String.eq`.
- **Type-level definitions.** `Pair`, spelled `A & B`, and `IO`. The generics
  suite let increment 6 defer them (`alias-type` is `agree-or-unsupported`).
  Here they are `agree`, because both are in the reached slice.
- **Sigma's dependent field.** `snd: B(fst)`.
- **`IO` as a higher-rank type.** `@-R: Type -> (A -> IO.OP<R>) -> IO.OP<R>`.
  `IO.bind` and `IO.die` are type lambdas, `R => k => ...`.

Also in the slice:

- `U32.read.go`'s nested pattern `SCon{Chr{x}, t}`.
- The multi-scrutinee matches of `Char.cmp`, `Char.is_eq`, `String.cmp` and
  `String.starts_with`.
- Twenty entries that the seed lowers natively on the JS lane: `Bool.or`,
  `Nat.cmp`, `String.append`, and 17 `U32` operations including `from_nat`,
  `to_nat` and `shrn`. On the native lane, `String.append` is source.
  `string-append-order` distinguishes the argument order for that reason.

## Knot requirements

| Requirement | Meaning |
| --- | --- |
| `agree` | Knot checks the fixture (exit 0). For every call in `observations`, the evaluator and the emitted Wasm return the recorded `result.tag`. |
| `agree-or-unsupported` | Either `agree`, or exit 3 with an `Unsupported` diagnostic and no artifact. `Invalid` never qualifies, because the seed accepts. |
| `unsupported` | Exit 3. stderr starts with the pinned diagnostic. No artifact. |
| `reject` | Never `Checked` or `Built`, and no artifact. Here every negative pins exit 2 (`Invalid`), because each is a misuse of Base signatures this increment must check. If a diagnostic is pinned, stderr starts with it. |

A pinned outcome carries `knot_expected: true` and a justification. In the
pinned diagnostics, `\t` stands for a tab, as in the other compiler suites.
`expectations.json` holds the exact strings.

- **`agree`: 25 fixtures.** Every program is in scope: its reached Base slice
  is Knot's own. That includes the pure core of IO. `IO`, `IO.OP`, `IO.bind`
  and `IO.die` are ordinary source definitions, and `io-pure-bind` observes
  them at the enum boundary by applying the IO value to the continuation
  `x => Emit{x}` and reading the resulting `IO.OP`.
- **`agree-or-unsupported`: `io-do-sequence`.** A `do IO<..>:` block is
  compiler-driver syntax (`driver.read_pair`, `compile-cli.write_pair`), not a
  Base form, even though it desugars to `IO.bind`. Baseslice may defer it.
- **`unsupported`, pinned `Unsupported\tcheck\thost-effect\t`: the four
  `io-*-helper` fixtures.**
  - **Form.** An uncalled helper in the driver's exact shape references Base
    host declarations:
    - `io-print-helper`: `IO.print`;
    - `io-args-helper`: `IO.args`;
    - `io-file-read-helper`: `File`, `File.open`, `File.read` and `File.close`;
    - `io-file-write-helper`: `File`, `File.open`, `File.write_bytes` and
      `File.close`.

    `main` stays pure and returns an enum. `do` blocks are written out as
    `IO.bind`, so every other form in these fixtures is in scope for baseslice,
    and the host reference is the first unsupported form.
  - **Why Unsupported.** The enum-only contract has no host imports
    (`hosts.json`, `knot_emitted_wasm`), and the IO host ABI is milestone 10.
    Knot checks and exports every top-level function, so the helper is
    reachable.
  - **Precedents.** The phase follows two existing pins:
    `Unsupported check constructor-fields`, which reports a capability the
    selected profile lacks, and the modules suite's
    `Unsupported check foreign-definition`.
  - **Why a new code.** A Base host effect becomes supported at milestone 10,
    while user foreign code stays excluded. `host-effect` covers foreign
    operations and the bodiless `File` alike, because either can be the first
    host reference.
  - **Controls.** An unreferenced Base foreign definition must not trigger it.
    Every `agree` fixture imports the same Base, with its 42 foreign
    definitions, and serves as that control.
  - **Veto.** This code is a reviewed literal. It may be vetoed before
    implementation starts. After that, changing it requires a recorded review.
- **`reject`: 10 fixtures.**
  - **Pinned codes.** Codes reuse the existing vocabulary where the reason is
    exactly the same:
    - `affine-reuse`: `reserved-affine` and `cmp-string-reuse`. String.eq and
      String.cmp consume their arguments.
    - `type-mismatch`: `read-maybe-quantity`, `concat-list-quantity` and
      `reverse-quantity`, where quantity arguments are invariant as in the
      generics suite's `quantity-invariant`; `shrn-u32-count`, where a U32
      numeral is passed for a `Nat` count; and `char-as-u32`.
  - **Class-only pins.** `length-missing-quantity`, `pick-missing-type` and
    `bind-missing-types` pin only exit 2. The seed finds a type or value where a
    quantity or type argument belongs, and no existing code names that.

The classification invariant holds for every fixture. When the seed accepts,
Knot never reports `Invalid`. When the seed rejects, Knot never reports
`Checked` or `Built`.

## Seed behaviours this suite freezes

These behaviours were observed while writing the suite. They are recorded
because an implementer could reasonably expect otherwise.

- **U32.read** (`u32-read-edges`):
  - It rejects overflow by checking `U32.div(n, 10) == acc` after each digit,
    so `"4294967295"` reads and `"4294967296"` and `"4294967300"` do not.
  - Leading zeros are free: `"00000000004294967295"` is the maximum and
    `"007"` is 7.
  - `""`, `"-1"`, `":"` and `"1/"` are `None`. The last two are the
    characters just outside `0`-`9`, where `U32.sub(x, 48)` wraps.
- **U32.show** (`u32-show-digits`) has its own zero branch (`"0"`), and a
  wrapped `U32.add(4294967295, 1)` shows as `"0"`.
- **String.cmp and Char.cmp** (`string-compare`, `char-cmp-rebuild`) hand both
  inputs back beside the order, and those inputs must be unchanged. Char order
  is unsigned: `'\u{80000000}'` sorts after `'b'`.
- **String.starts_with** (`string-starts-with`) accepts an empty prefix for
  every text, rejects a prefix longer than the text, and is case-sensitive.
- **Bool.pick** chosen at `String`, `U32` or a fielded type drops the other
  branch (`bool-pick-values`).
- **IO.die** short-circuits `IO.bind`: in `twice`, the first halt wins and its
  code and message survive (`io-pure-bind`).
- **Quantities.** Knot writes `List<&2, ..>` and `Maybe<&2, ..>` explicitly.
  The short forms `List<String>` and `Maybe<U32>` are `&1`, and the seed
  rejects them against Base signatures (`concat-list-quantity`,
  `read-maybe-quantity`). A missing quantity argument is reported as
  "expected Quant" (`length-missing-quantity`).
- **Nat literals.** `512n` and `257n` are past `256n`, so each is
  `U32.to_nat(n)` underneath (per the guide). `u32-natural-budget` and
  `u32-nat-bridge` compare such literals with `Nat.is_eq` and `Nat.cmp`.
- **Probes that shaped the fixtures but are not frozen:**
  - Applying a foreign operation inside a pure IO run leaves a stuck term:
    `outcome(IO.print("hi", Light, ...))` is printed unevaluated. Host effects
    therefore stay in uncalled helpers.
  - `Nat.is_eq(U32.to_nat(4294967295), U32.to_nat(4294967295))` did not finish
    in 60 seconds, because the interpreter's Nat work is unary. Nat values here
    stay at 512 or below.
  - A match on a computed value is a parser error, so fixtures give each
    scrutinee its own definition.
  - A live call to a definition declared below it fails with "a filled
    definition", so fixtures are ordered bottom-up.

## What the implementer wires

The gate runner, its receipts and the build lanes belong to the implementer.
Follow `tests/compiler-generics/FIXTURES.md` and `tests/compiler-wasm/check.py`.

1. Run `regen.py` first. It is the seed lane. Fixture hashes, seed hashes, the
   frozen slice and all observations must still match before anything else
   counts.
2. Build the check, eval and compile CLIs for the native and Bun lanes. For
   every fixture, check it, then compile it into an output file seeded with a
   marker. A rejected compilation must leave that file unchanged.
3. For `agree` fixtures, take each call in `observations`:
   - Evaluate `eval-cli <fixture> <entry> <budget> <ordinals...>`. It must
     yield `result.constructor`.
   - Run the emitted module with `node scripts/run-wasm.mjs`. It must return
     `result.tag`.
   - `ordinals` are the live enum arguments in parameter order. Several entries
     take `+` (reusable) enum parameters. Those are still live ordinals.
4. For the other requirements, apply the requirement table to every CLI phase
   that runs, including eval and compile.
5. Report blocked fixtures (see **Needs**) separately from passes and failures.
6. List the Base definitions each module lowers, and compare them with
   `base_reached`. Explain any extra, such as the `Word` helpers of an
   intrinsic lowered from source. D2 lowers only the reachable slice. The trust
   inventory of unchecked Base declarations is kept separately.

## Limits

- The seed lane is the reference interpreter. No seed-compiled binary is
  compared, although the census's per-lane boundaries are recorded.
- A seed-invalid fixture records only its direct rejection, because a wrapper
  cannot import an invalid module.
- Reach and coverage are static and syntactic: spelled names, constructors and
  literal sugar, closed over frozen census edges. They are not an execution
  trace and not the seed's emitted call graph.
- Nothing measures Knot's evaluator budget for these calls. Inputs are small
  (Nat at most 512, string literals under 40 characters), but an `Exhausted` result
  is inconclusive. It is never counted as a pass, and it is no reason to edit a
  fixture.
- The suite pins behaviour on finite programs. It proves no checker property.
- The Unsupported pins are scoped to increment 8. The increments that own those
  forms (the driver, milestone 10) will supersede them through reviewed
  amendments.
