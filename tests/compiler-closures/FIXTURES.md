# Closures fixture suite (campaign increment 7)

This suite freezes the expectations for increment 7 of the
[compiler campaign](../../docs/COMPILER-CAMPAIGN.md): closures and higher-order
code, lowered by defunctionalization with `return_call` (D3). It was written
before any implementation (D4, D7) and independently of the implementer.
Seed-valid programs take their results from the pinned reference interpreter,
Bend 2.0.29 at `574b6d3`. Knot-specific outcomes are reviewed literals in
`expectations.json`. No expectation comes from Knot output.

The implementer wires the gate runner and does not edit these expectations.
Changing a fixture, a case or a pinned outcome is a separately reviewed amendment.

## Contents

- `fixtures/*.bend`: 40 small programs, one feature or edge each.
  - Every fixture is ASCII with LF line endings and no tabs. None uses literals.
  - None imports Base. Each declares its own enums (`Flag`, `Color`, `Outcome`,
    `Shape`, and a one-constructor `Unit`) and its own carriers (`Res`, `Opt`,
    `Wrap`, `Pair`, `Bits`, and the `Type` datatypes `Fn` and `Fns`).
  - Seed-valid fixtures have a `main` plus a few entries. Entries take and return
    only nullary enums declared in the fixture, because the host boundary is
    enum-only. Every closure is built and consumed inside the program; no function
    value crosses the host boundary.
- `expectations.json`: all expectations, in these sections:
  - `seed`: version, revision and launcher path. These must equal `src/CONTRACT.json`.
  - `commands`: how every observation was produced.
  - `requirements`: the four Knot requirement kinds, defined below.
  - `cases`: hand-reviewed metadata for each fixture: class, feature, intent,
    twin, needed capabilities, entry signatures, the seed's rejection reason and
    the Knot requirement.
  - `observations`: generated by `regen.py`. It holds the seed file hashes, and
    for each fixture its source hash, its enum constructor orders, its
    `--check-only` and run results, and every entry call. A call records its
    wrapper source, argv, exit code, exact stdout and stderr, and its result
    `{type, constructor, tag}`. `tag` is the constructor's position in its
    declaration.
- `regen.py`: re-runs the seed and diffs the output against `observations`.

## Regenerating and checking

```sh
python3 tests/compiler-closures/regen.py          # re-run the seed; exit 1 on any difference
python3 tests/compiler-closures/regen.py --write  # rewrite observations only; review the diff
```

The script runs the seed as `bun .toolchain/bend-2.0.29-574b6d3/bend2/main.ts`,
from the repository root, with `BEND_NO_TELEMETRY=1` and relative paths. It is
deterministic, and its recorded output does not depend on the checkout. It takes
about twelve seconds. Wrappers are written to the ignored
`.local/compiler-closures/wrappers/` directory.

- **Observation shapes.** For `main`, the observation is a direct run of the
  fixture, so stdout is unqualified (`On{}`). Every other entry is called through
  a wrapper that imports the fixture as `F`. Its stdout therefore carries the
  import path, `../../../tests/compiler-closures/fixtures/<case>.On{}`, and
  `result` strips that prefix.
- **Failure conditions.** It fails in any of these cases:
  - the fixture files differ from the cases;
  - a Knot requirement is malformed, or disagrees with its class (positive and
    edge fixtures require `agree`, boundary fixtures `unsupported` or
    `agree-or-unsupported`, negatives `reject`);
  - a negative names no twin, a seed-valid fixture names one, or a twin is not a
    seed-valid case of this suite;
  - the seed accepts a fixture marked `reject`, or rejects one that is not;
  - a negative's `seed_reason` substrings are missing, meaning the seed
    rejected it for a different reason;
  - an entry uses a non-enum type;
  - the seed times out;
  - the seed identity or file hashes changed;
  - a recorded output contains a checkout-specific path.
- **Bootstrapping.** `--write` never touches `cases`. After running it, read the
  diff by hand.

### What Knot's own source needs

Across the compiler, its packages and Base, the census
(`docs/compiler-campaign/inventory/implementation.json`) finds lambdas in 172
declarations, captures in 168, function-typed parameters (`higher-order`) in
72, calls headed by a bound variable in 56, partial applications in 9 and named
definitions used as values in 5. The suite pins their shapes:

- `S.choose(A, c, u => ..., u => ...)`: `choose-thunks`, and the exact signature
  in `generic-choose-bind`, including an instance at a function type.
- `S.bind(A, B, r, +x => S.bind(..., y => ...))`: `bind-continuation`,
  `generic-choose-bind`, and the `+binder` in `lambda-reusable-binder`.
- Curried continuations such as `next: E.Scope -> C.Binding -> C.Term -> R`,
  applied as `next(a, b, c)` and fed `a => b => c => ...`: `curried-continuation`.
- A self-call inside a continuation lambda, as in `src/patterns.bend` `fields`:
  `cps-fold` (`nested`).
- Partial application such as `read_pair(characters, depth)` and named
  definitions passed as values: `partial-application`, `lambda-apply`,
  `defunc-sites`.
- IO continuations (`src/driver.bend`) and `do` blocks over IO stay out: they
  need Base's IO. `do-block` covers the desugaring over a fixture monad.

## Knot requirements

| Requirement | Meaning |
| --- | --- |
| `agree` | Knot checks the fixture (exit 0). For every call in `observations`, the evaluator and the emitted Wasm return the recorded `result.tag`. |
| `agree-or-unsupported` | Either `agree`, or exit 3 with an `Unsupported` diagnostic and no artifact. `Invalid` never qualifies, because the seed accepts. |
| `unsupported` | Exit 3. stderr starts with the pinned diagnostic. No artifact. |
| `reject` | Never `Checked` or `Built`, and no artifact. If `exit` is pinned, only that outcome class qualifies. If `diagnostic` is pinned, stderr starts with it. Otherwise exit 2 or 3 qualifies. |

A pinned outcome carries `knot_expected: true` and a one-line justification.

- **Reused codes.** Pinned `Invalid` codes reuse the existing vocabulary where
  the reason is exactly the same:
  - `affine-reuse`: a closure or a captured affine value used twice.
  - `reusable-type`: a `+` binder, parameter or lambda, at a function type.
  - `data-field-kind`: a function-typed field in a `Data` datatype.
  - `erased-live`: an erased capture returned live.
  - `unmatchable-binder`: a match inside a lambda body. The seed reason is the
    one `tests/compiler-checker/fixtures/match-after-let.bend` pins.
  - `not-callable`: a call headed by a variable of enum type. The seed reason is
    the one `tests/compiler-checker/fixtures/local-shadow-call.bend` pins.
  - `type-mismatch`: a function value of the wrong domain.
  - `annotation-required`: a let-bound lambda without an annotation.
  - `forward-live-call`: a lambda body calling a later definition.
- **Class-only pin.** `closure-over-applied` pins exit 2. Closure application
  belongs to increment 7, but the extra argument could reasonably be named
  `call-arity` or `not-callable`, so the implementer chooses the code and
  records it.
- **Recursion precedent.** `partial-self-same` pins
  `Unsupported\tcheck\trecursive-call\t`, the outcome `tests/compiler-recursion`
  pins for its non-descending `same-parameter` self-call. A partial self-call is
  still a self-call.
- **Pinned `Unsupported`.** `template-map` must report
  `Unsupported\tparse\ttemplate-binder\t`. The `~f` binder in the parameter list
  of `map` is the first form outside increment 7 (templates are S3). The code is
  the one in `src/parse.bend`, the `src/SPEC.md` table and
  `tests/subsets/classification-cases.json` (`template.bend`).
- **Open boundaries.** `do-block`, `dependent-arrow` and `lambda-match` are
  seed-valid forms that `src/` does not use outside IO. Increment 7 may cover them
  or report them `Unsupported`; it may never report them `Invalid`.

The classification invariant holds for every fixture. When the seed accepts,
Knot never reports `Invalid`. When the seed rejects, Knot never reports
`Checked` or `Built`.

The **Needs** column lists capabilities outside increment 7:
- `fields`: fielded constructors (increment 2, `knot-fields-wasm-1`). Storing a
  closure in a field (`closure-field`, `closure-list`) is increment 7's own work.
- `recursion`: structural self-calls (increment 1). Every self-call in a
  positive or edge fixture passes the first-parameter rule: its first argument is
  a field of parameter 0, directly or through a capture. Recursive Wasm lowering
  is not yet qualified.
- `generics`: erased type parameters and generic datatypes (increment 6).
- `templates`: S3.
- `do-notation`: `do` desugaring, S3.
- `dependent-function-types` and `lambda-match`: not on the increment 7 ladder.

A fixture is blocked while a need it names is unavailable. The runner reports
such a fixture as blocked. It never relabels it as passing and never re-expects it.

## What the implementer must wire

The gate runner, its receipts and the build lanes belong to the implementer.
Follow the pattern of `tests/compiler-fields/check.py` and `tests/compiler-wasm/check.py`.

1. Run `regen.py` first. It is the seed lane: fixture hashes, seed hashes and
   all observations must still match before anything else counts.
2. Build the check, eval and compile CLIs for the native and Bun lanes. For
   every fixture, check it, then compile it into an output file seeded with a
   marker. A rejected compilation must leave that file unchanged.
3. For `agree` fixtures, take each call in `observations`:
   - Evaluate `eval-cli <fixture> <entry> <budget> <ordinals...>`. It must
     yield `result.constructor`.
   - Run `node scripts/run-wasm.mjs <module> <entry> <ordinals...>`, with the
     profile the increment defines. It must return `result.tag`.
   - `ordinals` are the live enum arguments in parameter order. Every entry in
     this suite has only live enum parameters. Function-typed parameters of
     internal definitions never cross the host boundary.
4. For `agree-or-unsupported`, `unsupported` and `reject` fixtures, apply the
   requirement table to every CLI phase that runs, including eval and compile.
5. Report blocked fixtures (see Needs) separately from passes and failures.

- `call-arity` still rejects `identity()` at a `Flag` result

  function type becomes callable.

## Seed behaviours this suite freezes

These behaviours were observed while writing the suite. They are recorded
because an implementer could reasonably expect otherwise.

- **Closures are affine.** A closure can be applied at most once, even when every
  capture is Data (`closure-twice-data`). Function types are `Type`, never Data:
  a `+` parameter or lambda binder at a function type is rejected
  (`reusable-function-param`, `reusable-closure-binder`), and so is a function
  field in a `Data` datatype (`function-field-data`).
- **Captures are consumed when the closure is built**, not when it runs. Two
  thunks that capture one affine value are rejected although only one runs
  (`capture-affine-twice`). Each branch may capture its own affine value, or
  both may share a `+` value (`choose-thunks`).
- **Erased positions consume nothing.** A lambda passed to an erased parameter
  may capture a value that is also passed live, and a closure may use an erased
  capture as an erased argument (`erased-closure-arg`). Returning it live is
  rejected (`erased-capture-live`).
- **There is no seed-valid `map` with a closure parameter.** Applying `f` to the
  head and passing it to the self-call uses it twice (`map-reuses-function`).
  Base writes `List.map` as a template. The seed-valid alternatives are a list
  of closures (`closure-list`), continuation passing (`cps-fold`) and a template
  (`template-map`, a boundary).
- **No match inside a lambda body.** Neither the lambda's binder
  (`lambda-matches-binder`) nor a captured definition parameter
  (`lambda-matches-capture`) is a scrutinee. A definition whose match arms
  return different lambdas is accepted (`closure-in-arm`). The seed's
  `Location:` line names no definition for this error, so the reviewed reason
  quotes the marked source line.
- **Lambdas are not inferred.** A let-bound lambda needs an annotation
  (`unannotated-let-lambda`); `g = gate(k)` infers from the call
  (`return-closure`).
- **Application is curried.** `f(a, b)` is `f(a)(b)`: a definition that returns
  a closure may be over-applied, and a curried closure variable may be
  under-applied (`curried-arities`, `curried-continuation`). Applying past the
  arrow gives the seed's non-function reason (`closure-over-applied`), the same
  one as for an enum variable (`apply-non-function`).
- **Partial self-calls follow the descent rule.** `walk(t)` is accepted
  (`partial-self-call`, an S2 exit gate); `walk(xs)` is rejected
  (`partial-self-same`). A self-call inside a continuation lambda descends
  through a captured field (`cps-fold`).
- **Lambda binders are lexical.** A lambda binder shadows a parameter, and in
  `x => x => x` the inner binder wins (`nested-capture`).
- A lambda body's live call to a later definition gets the seed's
  "a filled definition" reason (`lambda-forward-call`).
- These probes are not frozen, but they shaped the fixtures:
  - A bare self-reference used as a value, `apply(spin, x)` inside `spin`, is
    rejected with the descent reason.
  - A lambda checked against `Flag` reports `observed : non-inferrable term`.
  - `+y => match y:` is rejected like `y => match y:`.
- Tags come from a syntactic reading of each fixture's enum declarations, in
  declaration order. The seed only names the constructor.

## Limits

- The seed lane is the reference interpreter. No seed-compiled binary is compared.
- A seed-invalid fixture records only its direct rejection, because a wrapper
  cannot import an invalid module.
- The suite pins behaviour on finite programs. It proves no checker property and
  no defunctionalization theorem.
- Continuations stay short (three list elements). The suite does not measure
  stack depth or show that `return_call` removes it; that belongs to the
  implementer's exhaustion probes and the benchmark framework.
- Unsupported pins are scoped to increment 7, and the increments that own those
  forms will supersede them through reviewed amendments.
