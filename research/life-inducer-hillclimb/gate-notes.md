# Gate adapter interface

`gate.py` is import-only for its public interface. Importing it makes no provider
calls. The parent owns candidate snapshots, round limits and final pass selection.

```python
check_files(lock=None)
evaluate_behavior(candidate, outdir, unique_id, *, lock=None)
evaluate_reviews(candidate, outdir, neutral_path, cohort,
                 previous_style=None, *, lock=None)
```

`lock` accepts a JSON path or a dictionary. The default is this directory's
`input-lock.json`. Its `frozen_files` maps repository-relative paths to SHA-256;
`judge_model` pins the observed provider model and defaults to `jev-1.13.0`.
`BEHAVIOR_PINS` and `REVIEW_FILES` expose the minimum required input inventories.
The cache module introduced by main `f1a4364` is included. A final lock should
also include this adapter and the experiment's other fixed inputs. No final
lock is generated by this module.

Each evaluator creates an exclusive stage-start marker and receipt in `outdir`.
Existing receipts or unfinished markers cause `configuration_failure`, without
overwriting evidence or dispatching another command. Completed-round replay
belongs to the parent controller. All returned receipt paths are repository
relative when possible.

Behavior writes `behavior.json`, command records in `behavior-commands/`, and
the outer command record `behavior-command.json`. The exact legacy receipt is
compressed into `behavior-raw-<unique_id>.json.gz`; `raw_sha256` hashes that file
and `raw_uncompressed_sha256` hashes its original bytes. Exact failed cases are
retained in `behavior-failures.json.gz`. Only the raw file created by this attempt
is removed after compression. The compact `counts` map retains each executed
runtime's fixture, composition and failure counts. A bad Node result stops the
frozen evaluator before Bun/native, as it did in the original experiment.

Behavior code is compiled directly from the hash-pinned historical evaluator.
The adapter changes only two old lock-path references and one ignored work-root
literal in its AST; those replacement counts are checked. It replaces subprocess
transport to retain full command outputs and preserve the original 60-second
command limits. The worker has a 480-second outer bound. Original behavioral
functions, assertions, fixtures and oracle files are unchanged. Work roots are
unique under `.local/life-inducer-hillclimb/behavior/`.

Review writes `reviews.json`, `semantic.json`, `semantic-usage.json`,
`style.json.gz`, `style-policy.json`, and exact command records. The returned
`semantic_receipt` and `style_receipt` identify available raw review results;
they remain null if that stage produced none. There is one semantic npm wrapper
call and one full-file style call, each bounded to two workers. No automatic
retry is performed. A semantic failure stops before style dispatch. Semantic
findings remain unresolved attention; the adapter never edits candidates.

Neutral paths must be `.bend` files beneath `.local/life-inducer-hillclimb/`.
The parent assigns one stable, unique path per trajectory. A filesystem lock
protects each neutral directory while its copy and both reviews run. Explicit
`previous_style` reuse is permitted only for the same neutral path, model and
rubric; the pinned style tool performs exact source/context identity checks.
Incremental cache mode is not requested and unexpected use is rejected.

Review acceptance checks resolved models, source/context hashes, complete
coverage, untruncated contexts and the current full v3 policy. Required
assessments are independently recomputed from retained Score distributions
using the frozen style policy implementation. This includes conditional
Galaxy-brain requirements and both Anticipation and Payoff targets. The result
includes required/met totals, per-axis totals, criticality and partial selection
metrics. A review pass alone is not a behavior pass; the controller combines
both `passed` fields.

Statuses are `passed`, `attention`, `deterministic_failure`,
`evaluation_failure`, `configuration_failure`, or `provider_failure` as
applicable. Provider/authentication/credit/noncompleted-review failures stop
review dispatch. Lock, integrity and model mismatches are configuration
failures. Candidate-attributable zero coverage or truncated context can be
attention. All failures retain exact command outputs when a command ran.

## Local verification

No model calls were made while implementing or testing this adapter.

- Behavior receipts:
  `.local/life-inducer-hillclimb/gate-test/20260926-211638/summary.json`.
  The historical round-06 program passes 1,537 fixtures and 21 composition
  checks under each of Node and Bun, plus 28 native fixtures. Identity,
  extinction and one-step controls fail with 1,475, 1,044 and 573 Node failures.
  Compressed raw receipt hashes and decompressed bytes agree. A repeated stage
  is refused while its original receipt remains byte-identical.
- Post-rebase offline policy and failure checks:
  `.local/life-inducer-hillclimb/gate-test/offline-20260926-211931/summary.json`.
  Seventeen checks cover a full critical-function pass; Galaxy-brain and
  diagnostic failures; critical datatype and noncritical diagnostic treatment;
  uncertain criticality; model, context, provider coverage, cache, v2 and
  freshness rejection; unresolved semantic findings; one-attempt provider
  failure; replay refusal; and lock rejection before dispatch.

The behavioral controls preceded the second rebase; post-rebase hashes confirm
all historical behavior inputs remain identical. The later failure-receipt
compression change did not alter the behavioral evaluator. Live provider
acceptance is deliberately unrun here and belongs to the bounded experiment.
