# Local Kev-4B review trial — 2026-09-26

**Disposition: running locally; promising separation on this small sample, but
not qualified to replace the default Bend reviewer.** Kev completed all 15 frozen
Laya requests on this Mac through its native MLX backend. At a fixed 0.5 split,
the corresponding defect questions classified 6/8 controls correctly, compared
with Laya's 4/8. Kev missed both growing-prefix defects; it correctly accepted
all four clean controls. No prompt, threshold, rule or code was adjusted for Kev.

The user requested Kev after the [Laya experiment](laya-local-2026-09-26.md).
This is Jared Palmer's Kev-4B, a local System One decision model with a pointer
head. It returns Noul, Choice and Score distributions directly, without generated
JSON or a hosted inference service.

## Runtime and replay

- Runtime: [jaredpalmer/kev](https://github.com/jaredpalmer/kev), commit
  `5920c5fe4ca8e0970ed4209ac2c9b8e18bea5109`; dependencies from its frozen `uv.lock`.
- Adapter: [jaredpalmer/kev-4b](https://huggingface.co/jaredpalmer/kev-4b), revision
  `139fdd94f1b6a6ad80cc15e08fcb99cac885a101`.
- Base: `Qwen/Qwen3.5-4B-Base`, revision
  `1001bb4d826a52d1f399e183466143f4da7b741b`; approximately 9.3 GB of base weights.
- Native MLX inference, bfloat16 backbone, checkpoint temperature
  `2.406050072164233`. No quantization or finetuning was added.
- Python 3.12.13; torch 2.8.0; MLX 0.32.2; mlx-lm 0.31.3;
  transformers 5.17.0; tokenizers 0.23.2.

The installed runtime and weights live under ignored `.local/kev/`. The
[runner](../scripts/kev-review.py) refuses a different runtime commit or modified
tracked runtime source and loads the exact local checkpoint with Hub access
disabled. Setup is complete in this checkout. Fresh Apple Silicon setup:

```sh
mkdir -p .local/kev
git clone https://github.com/jaredpalmer/kev.git .local/kev/repo
git -C .local/kev/repo checkout --detach 5920c5fe4ca8e0970ed4209ac2c9b8e18bea5109
UV_CACHE_DIR="$PWD/.local/uv-cache" uv sync --project .local/kev/repo \
  --python 3.12 --extra serve --no-dev --frozen
npm run review:kev -- --download
```

```sh
npm run review:kev -- --input docs/laya-trial/requests.json \
  --output .local/kev/replay.json
npm run review:kev -- --audit-only --input docs/laya-trial/requests.json \
  --output .local/kev/audit.json
.local/kev/repo/.venv/bin/python tests/kev-review.test.py
```

Exit 0 means the requested inference or audit completed, not that code passed
lint. Existing evidence files are never overwritten. Oversized inputs are rejected
before loading the model. The runner bounds state at 2048 tokens and each
state-plus-question row at 4096 tokens. It is experimental tooling, not a
general-purpose server. No server remains running and the normal Perch endpoint
is unchanged.

## Frozen comparison and input integrity

The exact [15 requests](laya-trial/requests.json) committed in `b04a38a` were reused.
Each runtime uses its native structured-state rendering and tokenizer; identical
request objects do not imply identical token sequences. Only `state` and
`questions` reach Kev. Expected outcomes, family labels and paths remain receipt
metadata. Native Noul options are `no`/`yes`; Score options contain every full
level description. Kev's standard delimiter escaping is retained; none of these
inputs requires it.

All requests fit completely: code state lengths were 198–343 tokens; the largest
packed request was the three-axis style request at 1308 tokens. An independent
uncut token construction matched every preflight sequence. The model's own
encoding then matched that preflight before each inference. No state, instruction
or option was clipped. State prefixes are shared within a request, with no cache
reuse across requests in this runner.

[Raw results](kev-trial/results.json) retain native answers, distributions,
encoding identities, context sizes and measured times. The
[comparison](kev-trial/comparison.json) records the fixed threshold, per-control
outcomes and frozen style targets. [Provenance](kev-trial/provenance.json) pins
runtime, tokenizer, adapter, base weights, inputs and historical oracle evidence.

## Semantic results

The first four requests ask whether the full growing-prefix requirement holds.
Kev answered 0.5556/0.5580 for clean/broken original code, and 0.5413/0.5266 for
the previously held-out clean/broken pair. At 0.5 it accepts all four, missing
both defects. Laya likewise accepted all four. These full-rule probabilities
are close to uncertainty and do not establish useful detection.

The next eight requests ask three narrower defect questions. The table gives
the corresponding question for each family; higher means a defect is present.

| Pair | Laya clean | Laya broken | Kev clean | Kev broken |
| --- | ---: | ---: | ---: | ---: |
| Growing prefix, original | 0.8888 | 0.8999 | 0.2248 | 0.3591 |
| Growing prefix, previously held out | 0.8646 | 0.6591 | 0.1819 | 0.3496 |
| Invariant summary | 0.8146 | 0.7704 | 0.3153 | 0.6139 |
| Linked-list indexing | 0.9291 | 0.9414 | 0.1756 | 0.5611 |

Kev ranks each pair in the expected direction, but only invariant-summary and
linked-list defects cross 0.5. That yields six correct decisions, zero false
positives and two false negatives. The narrower questions remain experimental
detectors, not accepted replacements for the complete rules. These are eight
observations, not a general accuracy estimate. No threshold was fitted to them.
The prior held-out cases were already observed during Laya prompt development;
they are not a fresh independent qualification set.

Both natural-language sanity controls behaved as expected: cancellation threat
0.9196 versus absence 0.1442; Choice selected billing at probability 0.7828 and
technical at 0.9015. This confirms state-dependent inference on those controls.

## Frozen style result

Kev accepted the complete three five-level rubrics frozen for the Laya trial,
including the long memetic descriptions that Laya rejected. On
`tests/perch-style/a.bend::solve`, the results were:

| Axis | Expected level (0–4) | Native confidence | P(level ≥ 3) | Frozen target |
| --- | ---: | ---: | ---: | --- |
| Maximally big brain | 2.1462 | 0.1123 | 0.3922 | unmet |
| Delightful to read | 2.2450 | 0.2072 | 0.4255 | unmet |
| Highly memetic | 1.8051 | 0.1456 | 0.2908 | unmet |

Each frozen target requires at least 0.6 probability at level 3 or above. These
distributions are broad and meet none of the targets. All three passed the
existing `validateScore` distribution-consistency check. That validates their
shape, not the quality or calibration of Kev's taste judgments. The supplied
context is untruncated but leaves `U32` operations unresolved as builtins.
No code was rewritten in response to these scores.

The concurrent style campaign has since expanded the rubric and added criticality
and diagnostic policies. This replay deliberately measures the frozen Laya
inputs; it does **not** evaluate or satisfy the current campaign gate. A single
scored example does not qualify Kev as a style judge.

## Timing, verification and disposition

Measured model load was 3064.8 ms; the first request took 2334.2 ms including
first-inference setup. The eight subsequent three-question code requests took
96.1–129.3 ms, median 99.8 ms. The frozen style request took 492.8 ms. These are
one-process local inference timings, excluding parsing, process startup and
model loading. They are not a throughput benchmark or a measured speedup over
the hosted reviewer. Laya's comparable warm code requests took 69.9–117.6 ms in
its earlier run, with a different runtime and execution order.

Seven focused offline tests passed against the actual Kev tokenizer: complete
frozen encodings, metadata isolation, full style descriptions, long options,
oversized state rejection, oversized branch rejection and empty-question
rejection. The npm audit command also completed all 15 requests. All eight code
hashes and the independent performance-oracle receipt still match the Laya
provenance. The deterministic performance oracle was verified by hash, not rerun.

Kev-4B is installed and usable as an opt-in local experiment. Its better ordering
and complete style-input support warrant further investigation, but the two
missed defects block replacing the default reviewer on this evidence. Fresh
independent controls would be needed after any checkpoint or prompt change.
No Bend implementation, accepted law, deterministic gate or default model was
changed for this trial.
